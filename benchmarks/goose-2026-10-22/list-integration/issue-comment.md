**Reading the table.** Values are medians of three runs; range is min–max successful req/s. RSS is summed service-process RSS sampled after load before shutdown, including Nginx where used; it is not peak or container memory and shared pages may be counted more than once. CPU includes live service-process work and CPU from waited/reaped children; 100% means one full server CPU. p95/p99 are medians of per-run histogram percentiles. Errors are totals over measured trials; warm-ups are excluded. A clean row requires zero HTTP and socket errors.

**wrk timeout accounting.** The [verified load binary](https://github.com/tbsvttr/twelve-dollar-server-challenge/blob/4f3c254a1a10eead6e9b1328f6b1758d6afbf313/benchmarks/2026-10-20/wrk-binary-provenance.json) is Ubuntu ARM64 wrk **4.1.0-4build2**. Its reported `timeout` counter counts completed responses whose recorded latency falls outside the default **two-second histogram range**. Those completions remain in request totals and req/s, while their latency samples are omitted from the reported maximum and percentiles ([package/source analysis](https://github.com/tbsvttr/twelve-dollar-server-challenge/blob/4f3c254a1a10eead6e9b1328f6b1758d6afbf313/benchmarks/2026-10-20/diagnostics-wrk-timeouts.json), [completion accounting](https://github.com/wg/wrk/blob/4.1.0/src/wrk.c#L307-L322)). Successful req/s subtracts only the recorded HTTP-error rate; successful over-limit completions remain included. HTTP and timeout counters can overlap. Diagnostic p95/p99 values therefore omit these over-limit samples. The declared clean-ranking rule still requires zero HTTP and wrk socket-error counters across all three trials. Unfinished requests at test end do not automatically increment this timeout counter.
